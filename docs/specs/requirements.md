## 1. プロダクト概要

家族・友人・仕事仲間など**グループ単位**で使う共有 Todo アプリ。
個人タスク管理ではなく「グループでタスクを共有し、誰がどれだけ消化したかを可視化する」ことを核とする。

- タスクはグループ全員に共有され、全員がステータスを変更できる。
- タスクの溜まり具合に連動して体調が変化する**キャラクター**を育成要素として持つ。
- 収益化は **無料 + 広告 / 広告除去（買い切り）/ プレミアム（サブスク・グループ単位）** のハイブリッド。

### ターゲット / 差別化
- 既存の個人 Todo が強い領域なので「グループ・コラボ」「進捗の可視化」「キャラクター育成」で差別化する。

## 2. 技術スタック（推奨）

| 領域 | 推奨 | 備考 |
|---|---|---|
| フレームワーク | **Flutter (Dart)** | iOS / Android 単一コードベース |
| 状態管理 | Riverpod もしくは Bloc | どちらでも可。1つに統一 |
| バックエンド | **Firebase** | Auth / Firestore / Cloud Functions / FCM / Remote Config |
| DB | **Cloud Firestore** | グループのリアルタイム同期に最適 |
| 認証 | Firebase Auth | 匿名認証スタート → 後でメール等に昇格可 |
| 招待リンク | **Universal Links / App Links + Cloud Functions でトークン解決** | ⚠ Firebase Dynamic Links は提供終了済みのため使用しない。管理型を使うなら Branch 等 |
| プッシュ通知 | **FCM (Firebase Cloud Messaging)** | リマインド・差し戻し通知に使用 |


### `groups/{groupId}`
```
name: string

memberIds: string[]        // 参照高速化用の非正規化

memberLimit: number        // 無料: 6 / プレミアム: 無制限(=大きな値) ※Remote Configで可変
inviteToken: string        // 招待リンク用トークン
inviteTokenExpiresAt: timestamp?
createdAt: timestamp
```

### `groups/{groupId}/members/{userId}`
```
role: "owner" | "member"
joinedAt: timestamp
```

### `groups/{groupId}/tasks/{taskId}`
```
title: string              // 必須
dueDate: timestamp         // 必須（日付）
hasTime: boolean           // 時間まで入力されたか
dueTime: string?           // 任意 "HH:mm"（hasTime=true のとき有効）
priority: "high" | "mid" | "low"   // 必須
status: "not_started" | "in_progress" | "done"
createdBy: string          // userId
assigneeId: string?        // 担当者（プレミアム機能）
createdAt: timestamp
completedAt: timestamp?
completedBy: string?
```

### `groups/{groupId}/tasks/{taskId}/activities/{activityId}`
履歴・統計の元データ。タスク操作のたびに追記する。
```
type: "created" | "status_changed" | "sent_back" | "reminded"
userId: string
fromStatus: string?
toStatus: string?
createdAt: timestamp
```

### `users/{userId}/character`
```
condition: number          // 体調 0-100（バックログから算出）
equippedItems: string[]    // 装備（将来のガチャで入手）
baseStats: { ... }         // 基本ステータス
updatedAt: timestamp
```

> キャラクターは**ユーザー個人単位**（装備はガチャで個人取得するため）。
> 体調は所属する**全グループの未完了タスク総数**から算出する。

## 4. 機能仕様

### 4.1 タスク管理機能
- **追加**: 必須3項目 = タイトル / 期限（日付）/ 優先度。期限は任意で時間まで入力可。
- **優先度は `高 / 中 / 低` の3段階**。色分け: 高=赤 / 中=黄 / 低=グレー。
- 追加されたタスクはグループ全員に即時共有（Firestore リアルタイムリスナー）。
- **ステータス更新**: `未実施 → 着手中 → 完了` の3段階。グループメンバー全員が変更可能。
  - **誤タップ防止のため確認ダイアログ方式**にする。ステータスをタップ → ダイアログ表示 → 更新後のステータスを選択 → [更新]で確定 / [キャンセル]で変更なし。
  - [更新]確定時、**グループ全員に通知（FCM）**を送る（ただし通知ミュート中のメンバーには送らない。4.7参照）。
- **リマインド**: 期限前通知（FCM）。後述の通知設計を参照。

### 4.2 並び替えロジック（★厳密仕様）
タスク一覧は以下の比較順で昇順ソートする。

```
1. dueDate（日付）が早い順
2. 同一日付内: hasTime=true（時間あり）を hasTime=false（時間なし）より上
3. ともに時間あり: dueTime が早い順
4. priority: high > mid > low
5. createdAt が早い順（安定ソートの最終タイブレーク）
```

擬似コード:
```dart
int compareTasks(Task a, Task b) {
  // 1. 日付
  final d = a.dueDate.dateOnly.compareTo(b.dueDate.dateOnly);
  if (d != 0) return d;
  // 2. 時間あり優先
  if (a.hasTime != b.hasTime) return a.hasTime ? -1 : 1;
  // 3. 時間順
  if (a.hasTime && b.hasTime) {
    final t = a.dueTime.compareTo(b.dueTime);
    if (t != 0) return t;
  }
  // 4. 優先度（high=0, mid=1, low=2 で昇順）
  final p = priorityRank(a.priority).compareTo(priorityRank(b.priority));
  if (p != 0) return p;
  // 5. 作成順
  return a.createdAt.compareTo(b.createdAt);
}
```

### 4.3 達成タスク管理機能（自分のタスク）
- ログインユーザーが**追加（作成）したタスクのみ**を一覧化し、各ステータスを確認できる（担当者基準ではなく作成者基準）。
- **差し戻し**: 「完了」になっているが実際は未達成のタスクを、作成者が `着手中` 等へ戻せる（activity に `sent_back` を記録）。
- **リマインド送信**: `未実施` のタスクについて、グループ全員に通知を送る（activity に `reminded` を記録）。
- 連打防止のためリマインドはクールダウン（例: 同一タスク6時間に1回）を設ける。

### 4.4 グループのタスク履歴・統計機能
`activities` を集計してグラフ表示する。集計は Cloud Functions で定期/トリガー集計し、`groups/{groupId}/stats` にキャッシュすると軽い。

表示指標:
- メンバー別の**消化数**（完了タスク数）
- タスク発生（created）→ 完了（completed）までの**平均消化時間**
- **期限内完了率**（completedAt <= dueDate の割合, %）
- **ランキング**: 消化数ランキング / 消化スピードランキング

グラフは fl_chart など Flutter のチャートライブラリを使用。

### 4.5 キャラクター機能
- タスクが溜まると体調が悪化するキャラクターを表示。
- **この画面へ遷移する際、動画広告（インタースティシャル/リワード）を差し込む**（プレミアム=広告除去ユーザーには出さない）。
- **レベルの概念は無し。** ステータスは「装備」と「残タスク量」で変動（残量が少ないほどステータス高）。

体調・ステータス算出（初期案・Remote Config で調整可能）:
```
// pendingLoad = ユーザーが参加している【全グループ】の未完了タスク総数
//   （status が not_started または in_progress のタスク。done は除外）
//   ※自分が作成したものに限らず、所属グループ内の残タスクすべてを数える
pendingLoad = Σ(参加グループの未完了タスク数)
condition = clamp(100 - pendingLoad * k, 0, 100)   // k は係数（Remote Config）
displayStat = (baseStat + equipmentBonus) * conditionMultiplier(condition)
// conditionMultiplier 例: condition 0→0.5倍, 100→1.5倍
```
- 見た目は condition の段階（健康 / 疲労 / 不調）で差し替え。
- キャラは**ユーザー個人単位**。複数グループに所属する場合は**全グループの残タスクが合算**されて体調に影響する。

**将来拡張（今回は未実装・設計上の余地だけ残す）:**
- 装備ガチャ（見た目+ステータス変化）。課金通貨 or リワード動画でガチャ回数獲得 → **広告/IAP のもう一つの収益エンジン**になる。
- キャラを連れて行くミニゲーム。
- → `equippedItems` / `baseStats` は拡張前提のスキーマにしておく。

### 4.6 グループ管理・認証（招待リンク）
- 初回は **Firebase 匿名認証**で開始（登録ハードルを下げる）。
- **アカウント登録は必須機能**（MVPに含める）。匿名アカウントを正式アカウントに昇格させる方式で実装する。
  - 登録方法: メール / Google / Apple サインインのいずれか（iOS配布では Sign in with Apple が必須要件になりうる点に注意）。
  - 登録トリガー: グループの作成・参加など共有データに関わる操作の前に登録を要求する。
  - 登録により端末変更時のデータ引き継ぎが可能になる。
- グループオーナーが**招待リンク**を発行。
- リンクは Universal Links / App Links で開き、`inviteToken` を Cloud Functions で検証してグループに参加させる。
- アプリ未インストール時はストアへ誘導し、インストール後に参加処理へ復帰できる導線にする。
- トークンには有効期限・再生成機能を持たせる。

### 4.7 通知設定（グループ別ミュート）
- ステータス更新などの通知は**グループ全員に送る**が、各メンバーは**グループごとに通知をミュート**できる（通知疲れ対策）。
- ミュート中のメンバーには、そのグループ由来の通知（ステータス更新・手動リマインド等）を送らない。
- 設定は `users/{userId}/notificationPrefs` に保持し、通知送信時（Cloud Functions）に判定する。
- 期限リマインドのON/OFFも別途持つ。

## 5. 収益化設計（無料 / プレミアムの2段構成）

| 層 | 内容 | 価格 |
|---|---|---|
| 無料 | 広告あり。コア機能はすべて使える | 無料 |
| プレミアム | **グループ単位**。オーナーが払うとグループ全員に適用。**広告除去 + 上級機能** | **¥600/月** |

> 広告除去はプレミアムに統合（単体の広告除去買い切りは設けない）。

### 広告配置（UXを壊さない原則）
- バナー: タスク一覧の最下部のみ（操作の邪魔をしない）。
- **動画広告: キャラクター画面への遷移時**（自然な切れ目をキャラ機能で作る）。プレミアムでは非表示。
- 起動直後・タスク追加/操作の最中には全画面広告を出さない（アンインストール要因）。
- 将来のガチャは「リワード動画を見ると無料で1回」を入口にできる。

### 課金設計の原則
- **コア体験（3項目で追加→共有→ステータス変更）は無料に残す。** 課金は「規模（人数・グループ数）・連携・通知・上級機能・広告オフ」に置く。
- プレミアムは**オーナー1人の支払いでグループ全体が解放**される方式（転換率が上がり解約しにくい）。

## 6. 無料 / プレミアム 機能境界表

| 機能 | 無料 | プレミアム |
|---|---|---|
| グループ作成・参加 | ◯（グループ 3まで / 人数 6まで） | ◯（無制限） |
| タスク追加・共有・ステータス変更 | ◯ | ◯ |
| 期限順ソート | ◯ | ◯ |
| 基本リマインド | ◯ | ◯ |
| キャラクター表示 | ◯（遷移時に動画広告） | ◯（広告なし） |

| 担当者アサイン | ✕ | ◯ |
| コメント / 添付 | ✕ | ◯ |
| 繰り返しタスク | ✕ | ◯ |
| 高度な通知 | ✕ | ◯ |
| 広告 | あり | なし |

> 数値（人数上限6・グループ数3・履歴期間）は **Remote Config** で後から調整できるよう実装する。

## 7. 画面構成

**下部ナビ（5タブ）: `タスク / Myタスク / 統計 / キャラ / 設定`**

1. **オンボーディング / 認証**（匿名サインイン、アカウント登録、招待リンク経由の参加）

6. **グループ統計 / ランキング**［タブ:統計］（グラフ表示）

## 8. 通知設計（FCM）

| トリガー | 宛先 | 内容 |
|---|---|---|
| 期限前リマインド | 関係メンバー | 「期限が近いタスクがあります」 |
| 手動リマインド（4.3） | グループ全員 | 「未着手のタスクがあります」 |
| 差し戻し | 対象タスク関係者 | 「タスクが差し戻されました」 |
| **ステータス変更** | **グループ全員** | 「○○が△△に更新されました」 |

- すべての通知は、**そのグループをミュートしているメンバーには送らない**（4.7）。
- 通知トリガーは Cloud Functions（Firestore トリガー / スケジュール）で実装。送信前に各受信者の `notificationPrefs` を確認する。

## 9. 後から調整できる構造（重要）

- **エンタイトルメント（課金状態）は RevenueCat + サーバー側で判定**。クライアントを信用しない。
- **広告頻度・無料/有料境界・人数上限・キャラ係数 k は Remote Config** で配信時に変更可能にする。
- 広告は AdMob メディエーションで複数ネットワークを束ねる。
- これにより「最初に決め切らず、リリース後に数値を見て寄せていける」状態を作る。

## 12. 確定事項（決定済み）

1. **優先度**: `高 / 中 / 低` の3段階。色分け 高=赤 / 中=黄 / 低=グレー。
2. **キャラクター**: ユーザー個人単位。複数グループ所属時は**全グループの未完了タスク総数**が体調に影響。
3. **無料枠**: メンバー上限 **6人** / グループ数 **3まで**（プレミアムで無制限）。※すべて Remote Config で可変。
4. **価格**: プレミアム **¥600/月**。プレミアムにすると広告除去。単体の広告除去買い切りは無し。
5. **「自分のタスク」**: 自分が**作成したタスクのみ**（作成者基準）。
6. **体調算出**: 所属する**全グループの未完了タスク（not_started + in_progress）の総数**。
7. **認証**: 匿名認証スタート + **アカウント登録は必須機能**（MVPに含む。匿名→正式アカウント昇格方式）。
8. **下部ナビ（5タブ）**: `タスク / Myタスク / 統計 / キャラ / 設定`。
9. **ステータス変更**: 確認ダイアログ方式（ラジオ選択 + 更新/キャンセル）。誤タップ防止。
10. **ステータス更新通知**: グループ全員に送信。ただし各メンバーが**グループ別に通知ミュート**可能。

### 残る微調整（実装中に確定でOK）
- 体調算出の係数 k と conditionMultiplier の具体値（Remote Config で調整）。
- 履歴・統計の無料時の期間制限（例: 直近7日 or 30日）。
- 登録方法の最終選定（メール / Google / Apple）。iOS は他社サインインを入れる場合 Sign in with Apple が必須要件になりうる。
